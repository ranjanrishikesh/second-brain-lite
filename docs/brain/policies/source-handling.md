# Source Handling

Treat source evidence as retained, traceable material. Keep original evidence in `sources/raw/`, normalized material in `sources/extracted/`, canonical per-source inventory records in `sources/ledger/*.json`, and their generated summary in `sources/ledger.md`.

Each ledger record is canonical compact JSON with a trailing newline and is published by a flushed, synchronized same-directory temporary file followed by an atomic replacement. Readers accept only validated regular record files whose filename matches the embedded source ID; they do not follow symlinks or accept nonregular ledger entries. Repository, `sources`, ledger, raw, and archive directory edges are opened component by component and pinned by descriptor identity around each operation. If no-follow, directory, descriptor-relative stat/open/mkdir/unlink/link/replace, or descriptor-listing support is unavailable, ledger operations fail closed with a deterministic unsupported-filesystem error. The generated summary is deterministic for its synchronization timestamp and sorted records. It uses fixed source-row and gap-row byte budgets, records exact omitted counts, and can never exceed the same 16-MiB protocol limit enforced by its writer, reader, and validator. It reports the corpus revision, state counts, coverage gaps, record links, and active extracted-artifact links, but is never a second source of truth. Markdown destinations percent-encode path data while retaining path separators, and displayed paths and diagnostics escape Markdown-significant and control content.

`sources/raw/_versions/**` and `sources/raw/_web/**` are reserved, non-discoverable evidence stores. Only `_versions` or `_web` as the first raw-relative path component is reserved; directories with those names below an ordinary source directory remain discoverable source content.

Source discovery also excludes sentinel files named `.gitkeep`, `.keep`, or `.DS_Store`, temporary files whose basename starts with `.brain-tmp-`, and lock files whose basename ends with `.brain.lock`.

Inventory opens the repository, `sources/`, and `sources/raw/` directories without following symlinks, then lists and inspects every descendant relative to already-vetted directory descriptors. Every opened directory edge—including the `sources/` and `sources/raw/` anchor edges—is retained with owned parent/child descriptor observations and revalidated before and after content reads. Directories are reopened with directory/no-follow flags; content is opened with no-follow and nonblocking flags, required by `fstat` to be the same observed regular file, and rechecked around reads. A file symlink is eligible only when component-by-component descriptor-relative resolution remains beneath the pinned raw root and the resolved raw-relative target is not ignored or reserved. Escaping, broken, reserved-tree, directory, changing, and other unsafe aliases are reported as skipped and are never read. A platform without the required descriptor-relative and no-follow primitives returns a deterministic unsupported diagnostic instead of weakening this boundary. One unreadable or changing entry does not abort the rest of the deterministic raw-relative-path inventory.

Media detection reads only a bounded prefix and, for ZIP packages, bounded tail, central-directory, and local-header metadata; it never decompresses or hashes source bodies. OOXML recognition requires coherent single-disk, non-ZIP64 central and local records with unique package markers and bounded, nonoverlapping local offsets. PDF, PNG, JPEG, TIFF, WebP, and structurally valid OOXML package signatures take precedence over names. Valid UTF-8 is then classified with the approved text-family suffix vocabulary; only after those checks may a binary file's logical inventory suffix supply a fallback. The compound `.url.md` suffix is recognized before ordinary `.md`, including when an accepted symlink target has a different name. Inventory fingerprints contain the observed raw-relative path, byte size, and nanosecond modification time; their SHA-256 field remains unset until reconciliation decides hashing is necessary.

URL descriptors are local control metadata, not captured evidence bytes. A descriptor is UTF-8 frontmatter with exactly `kind`, `url`, `description`, and `added`; `kind` is `url`, `added` is a canonical `YYYY-MM-DD` date, and the URL uses HTTP or HTTPS. URL and description values may be conservative single-line plain scalars or JSON double-quoted strings. Canonical writers use `json.dumps(..., ensure_ascii=False)` so punctuation, escapes, and Unicode round-trip without YAML typing. Duplicate, missing, or unknown keys; multiline or collection forms; invalid JSON strings or dates; and invalid URL schemes produce an `invalid_url_descriptor` skip diagnostic. Parsing performs no DNS lookup, connection, or other network operation.

The descriptor file's fingerprint tracks mutable URL control bytes, but those bytes never create a content version. On first encounter, its source identity is the canonical path-sensitive source ID computed from the SHA-256 of `url-descriptor-v1`, a NUL separator, and the UTF-8 URL. Reconciliation preserves the already-ledgered source ID for later edits at that known descriptor path.

For file-backed schema-v1 records, the creation path and unique root content checksum permanently bind the source ID. Zero adoptions have exactly one version. One or more adoptions retain every version and form one complete ordered, nonbranching, nonrepeating chain from that root to the active checksum; every event names retained endpoints, and the adopted version's first-seen time equals the event time. Renames may change current and previous paths but never rebind the creation identity. URL-backed records retain their schema-v1 evidence ceiling; validators do not invent an unrecorded first-URL proof.

Do not add web evidence unless its research has been approved. Preserve source provenance when material moves between source stages.

An extracted representation is identified by the exact logical source ID, retained content checksum, and retained derivation ID. Active search views require a linked active content version and derivation. Exact historical lookups remain available for retained triples even when a source has no active representation. Extraction paths retain the complete raw basename beneath the source hierarchy: `<raw-parent>/<raw-name>/<content-sha256>/<derivation-id>.md`, relative to `sources/extracted/`.

Every processor attempt consumes only the descriptor-backed `ProcessingContext.input_path` or `input_descriptor` whose independently computed SHA-256 is `input_sha256`; it must not reopen `sources/raw/`. The source descriptor and all path edges remain pinned through the callback and are revalidated after the final activation checkpoint. Batches may copy only from that pinned descriptor into a private, fsynced, content-addressed stage whose descriptor remains open and is revalidated after the worker. External commands receive only that descriptor/stage authority through a proven inherited-handle mechanism and fail closed when the platform cannot provide one. Reconciliation independently stable-opens the exact canonical `EXTRACTED` artifact and matches its SHA-256, byte size, nanosecond mtime, path, and derivation identity. That output descriptor and its pinned path edges remain live through activation, event preparation, and the final shard checkpoint, then are revalidated; an equal-size/equal-mtime replacement rolls the shard back to `extracting` rather than leaving a stale claimed checksum. Claimed processor metadata is never evidence by itself.

Each init/sync appends and fsyncs exact hash, new-representation, rewrite, handoff, and gap observations to a recoverable journal. Shard-coupled representation and rewrite events use prepare/checkpoint/commit frames bound to the exact canonical post-record digest; recovery includes an interrupted intent only when that exact post-image is canonical. Before finalization, a bounded completion envelope is durably bound to both the journal digest and a strong digest of every full ledger shard, so finalization or pending-publication recovery cannot rerun reconciliation, accept altered recovery state, or mix another inventory. The immutable public JSONL manifest's header, sequence, event digest, exact per-kind counts, corpus revision, whole-file digest, and canonical path are verified through pinned no-follow reads. In-memory reports and CLI JSON contain exact counts but only deterministic 100-item/32-KiB samples plus the bounded manifest reference. The exact result stays pending across output and consumer failures. Clients retain the response reference and run `./brain --json source consume-sync-result --result-id "$result_id"`; its result ID, immutable `manifest_path`, revision, exact event counts, and effect digest must match. It verifies/drains the result and records a durable receipt without acknowledgement or mutation; clients read the path only for exact effects, apply/deduplicate by result ID, then separately acknowledge. `SyncResultStore.verify` and `iter_events` are implementation behind that CLI, not executable client instructions. Acknowledgement rejects a missing matching consumption receipt, remains idempotent after consumption, and only then removes the pending pointer. Wrong IDs fail closed.

When changed bytes put a source into `integrity_error`, never activate them in place. Approved adoption first rechecks the live file against the observed path, size, modification time, and candidate checksum. It then proves and materializes every prior retained version at `_versions/<source-id>/<content-sha256>/<original-name>` using an already-valid archive or exact Git history bytes. Archive paths must be regular files beneath the repository and are never overwritten when their bytes disagree. Every new or pre-existing archive directory edge is confirmed before its parent is synchronized. Before an exact existing archive is reused, its stable open file is synchronized and then its containing directory is synchronized; a retry after uncertain publication therefore cannot activate the record until durability has been completed. After all prior versions are materialized, adoption performs a final stable descriptor-relative reread of every archive and the live candidate; a changed name, type, byte stream, fingerprint, or pinned ancestor aborts record construction. Only that final coherent snapshot supplies the stored archive and live fingerprints. The handler preflights every ledger shard and the next summary before the record commit point. After any save result or exception, it freshly reopens the canonical shard and requires the exact canonical payload and record before it claims activation, returns rewrites, or refreshes the summary. A proven record with a post-publication or summary fault returns the exact citation rewrites plus a recovery warning; an unproved detached publication returns failure without rewrites and leaves the canonical summary untouched. URL descriptor control bytes are not content versions, and web retrieval-event bytes remain attached to their owning historical version.

Git recovery has one finite positive 30-second monotonic deadline across history enumeration, blob reads, and bounded cleanup. Revision output is capped at 16 MiB and must consist only of complete lowercase 40- or 64-hex revision lines in Git's newest-to-oldest order. Each candidate blob is capped at 1 GiB before checksum acceptance. These defaults accommodate large normal repositories and sources; callers may explicitly raise or lower the finite deadline and ceilings when constructing the resolver. Git receives an explicitly inherited environment with lazy object fetching disabled, terminal prompting disabled, and optional locking suppressed. Each invocation is owned by a new POSIX session/process group or a Windows kill-on-close Job Object. The whole tree is terminated even when a descendant retains stdout; leader waiting is bounded, and any stubborn final reap transfers to a daemon rather than extending the caller's deadline. Git stderr is discarded, and commands remain literal non-shell read-only argument arrays.

The committed `config/extractors.toml` registry is the only approved extractor allowlist. Registry entries are selected by an exact detected MIME match before a filename-extension match; overlapping extensions use the longest match, so `.url.md` is a single URL-descriptor suffix rather than an ordinary Markdown file. Unknown configuration keys and shell-bearing argument templates are invalid.

Converter commands are argument arrays, never shell programs or command strings. Runtime paths replace only the exact `{input}` and `{output}` tokens. Version detection may run only the allowlisted executable with its literal version arguments under the fixed probe limits, or read the declared Python distribution version. A probe that exceeds the time or output limit is killed, reaped, and treated as unavailable; oversized output is never silently truncated into a version. Installation recipes are reference data and never authorize the CLI to install or execute a converter.

Only the committed `builtin.text`, `builtin.tabular`, `builtin.json`, `builtin.html`, and `builtin.http-capture` adapters are always available. A new `builtin.*` spelling is invalid until its adapter implementation and registry admission ship together.

LibreOffice converters receive an isolated temporary directory as `{output}`. The adapter must find exactly one expected exported file, reject macros or unexpected siblings, and normalize that file into the final Markdown staging path. Tesseract writes to stdout captured by the parent process; `{output}` is never interpreted as shell redirection.

Each extractor has its own configuration digest. Changing one entry does not stale results from another entry. The selected converter ID and normalized installed version form that extractor's prerequisite digest, and the effective extractor version combines the committed extractor version with the full prerequisite digest.

`agent_fallback` does not authorize an LLM call. It permits the deterministic processor to return `needs_agent` and create a handoff when deterministic extraction is unavailable or explicitly classifies the source as visually complex. Such entries require a positive decimal `agent_revision`; an approved change to the agent recipe, prompt, vision method, or judgment procedure must bump that revision so prior handoffs and derivations remain immutable. Stored agent derivations permanently require exactly `handoff_id = hnd_` plus 64 lowercase hexadecimal characters, a canonical positive-decimal revision with no leading zero, and a nonempty trimmed NUL-free note. Historical validation checks this stored grammar but never compares it with today's registry or revision.

Importing the CLI, rendering help, and running `doctor` do not require `fcntl`. Doctor reports whether the safe source-write lock backend is available. On a platform without a proven backend, every lock-requiring command fails closed with one structured bounded diagnostic and performs no repository mutation. A checked lock context treats false or raised release as non-clean; it preserves a body exception as primary with a bounded cleanup note, while a lock already proven manually released exits idempotently.
